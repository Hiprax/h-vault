# Provenance — the format-and-repair corpus

Verified-By: maintainer (Hiprax)
Verified-On: 2026-09-01
Source: written by hand for this repository. Nothing here was downloaded,
generated by a tool, or minimized by one.

Checked: every file in this directory is hand-authored, and each is the smallest
input that still reproduces the shape it is named for. The reason each one
exists is recorded beside it in `../format-corpus.ts`, which is also where the
TRUTH TABLE lives: for each entry, which combinations of the two transforms must
fail and, by omission, which must succeed. Every value in that table was
MEASURED against `prettier@3.9.5` and `jsonrepair@3.15.0` on 2026-09-01 rather
than predicted — including the four that are counter-intuitive:

- `single-quotes.json` FORMATS without a repair, because Prettier's `json`
  parser is Babel's and reads a single-quoted string.
- `trailing-comma.json` formats too, which is why the panel must not claim that
  repair is the only thing that can fix a file.
- `empty.json` formats to itself and cannot be repaired: there is no document
  there to repair, and an empty success presented as a fix would be a lie.
- `comments.jsonc` and `unquoted-keys.json5` are printed by their OWN dialect's
  parser after a repair-then-format run, because the EXTENSION is what declares
  the dialect and the repairer has already turned the bytes into strict JSON.
  The dialect is therefore what read the document, not what came out of it:
  Prettier emits no trailing comma for `json`, `jsonc` or `json5`, and the
  comments the repairer stripped do not come back. Formatting WITHOUT a repair
  is the run that keeps them.

Two files are deliberately not UTF-8 text and are refused before any parser sees
them: `bom.json` (valid UTF-8 behind a byte-order mark, which `TextDecoder`
strips, so the round trip catches it) and `utf16.json` (UTF-16LE with NO
byte-order mark, every byte under 0x80, which decodes AND re-encodes
byte-for-byte identically — the round trip cannot see it, and its NUL characters
are what refuse it).

Not-verified: no third-party formatter other than Prettier was run over these,
and no claim is made about what any other tool would do with them. The YAML and
Markdown entries pin the engine's behaviour, not the specifications.

Recording: nothing regenerates these files. The suite in
`../format.fuzz.test.ts` only ever reads them, and `../format-corpus.ts`
compares the directory against its own index in BOTH directions, so a file added
here without an entry — which nothing would run — fails the suite.
